# Volleyball Recruiting CRM — PRD

## Original Problem Statement
Public-facing Volleyball Recruiting CRM evolving into a decision-support system for student-athletes via a three-stage intelligence pipeline (Schema Mapper → Payload Builder → Intelligence Runtime).

## Intelligence Pipeline — COMPLETE
All 5 micro-agents built, tested, and wired to the frontend. No cards remain on old heuristic logic.

| Agent | Label | Endpoint | Generated By |
|-------|-------|----------|-------------|
| School Insight | AI-generated | `POST /api/intelligence/school-insight/{id}` | AI |
| Timeline | Unknown / Fills Early / Standard / Late | `POST /api/intelligence/timeline/{id}` | Deterministic or AI |
| Roster/Stability | Unknown / Open / Limited / Tight + Stability | `POST /api/intelligence/roster/{id}` | Deterministic or AI |
| Scholarship | Mix of Partial and Full / Typically Partial / Walk-On Pathways Common / Unknown | `POST /api/intelligence/scholarship/{id}` | Deterministic or AI |
| NIL Readiness | Established NIL Support / Emerging NIL Support / NIL Information Limited | `POST /api/intelligence/nil/{id}` | Deterministic or AI |

## Design Principles (All Agents)
- AI determines ONLY the label; all UI copy hardcoded per label
- Honest defaults: "Unknown" / "Information Limited" when no stored signals
- No dollar amounts, no percentages, no guarantees
- Contributed data stays `pending_verification`, never auto-promoted
- Item-level citations with section + source_id
- Questions-to-ask section per card (collapsible + copy button)

## Data Enrichment System
- "Improve this card" nudge on Unknown/Limited-state cards
- Backend: `POST /api/intelligence/contribute` (link/request) + `/contribute/upload` (file)
- All stored as `pending_verification` in `intelligence_contributions` collection
