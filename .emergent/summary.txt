**Critical Info for New Agent**
Your top priority (P0) is to implement the new dynamic grouping logic for the Recruiting Board. The user has approved a specific set of rules after a detailed discussion. You must implement this logic exactly as specified.

**The Approved Grouping Logic (in priority order):**
A school should only appear in the *first* group it qualifies for.

1.  **Closed**: A school goes here if its status is explicitly marked as Not a Fit, Committed Elsewhere, or Recruiting Closed. (Check first).
2.  **In Progress**: A school goes here if it was contacted within the last 7 days OR has an active conversation (e.g., coach replied), AND has nothing overdue.
3.  **Upcoming**: A school goes here if it has a follow-up date set within the next 14 days, AND it was not recently contacted (i.e., doesn't qualify for In Progress).
4.  **Action Required**: A school goes here if it matches none of the above criteria. This is the **default catch-all group** for anything that is overdue, has a reply that needs a response, or has become stale.

Your task is to:
1.  Modify the backend endpoint (likely ) to categorize schools into these four groups based on the rules.
2.  Update the frontend () to render these four groups and the schools within them.
3.  Update the mock data to ensure schools appear in all four categories for testing purposes.
